## Usage

```bash
joflux [--config PATH] [--log-level LEVEL] <command> [flags]
joflux --version
```

The global options go before the command; each command's own flags go after it. A command is
required, and running `joflux` on its own prints usage.

## Commands

| Command | What it does | Reads | Writes |
| --- | --- | --- | --- |
| [`export`](/joflux/stages/export/) | Lists the GitHub organization's repositories | GitHub | `repos-inventory.json` |
| [`migrate`](/joflux/stages/migrate/) | Asks Forgejo to migrate each repository | `repos-inventory.json` | `migration-log.json` |
| [`monitor`](/joflux/stages/monitor/) | Rechecks migrations Forgejo didn't answer for | `migration-log.json`, `migration-status.json` | `migration-status.json` |
| [`verify`](/joflux/stages/verify/) | Checks each repository on the target and counts its contents | `repos-inventory.json` | `verification-report.json` |
| [`archive`](/joflux/stages/archive/) | Archives the GitHub originals | `repos-inventory.json` | `archive-log.json` |

## Logging

Log lines go to standard output in the shape `HH:MM:SS - LEVEL - message`, with the level coloured
when the output is a terminal. A config error is printed to standard error as
`config error: <reason>` instead, because it happens before logging is set up.

Every command exits 0, 1, 2 or 130; [Exit codes](/joflux/reference/exit-codes/) has what each means.
